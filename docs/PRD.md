# FictionForge 产品需求文档（PRD）

**文档版本**：v0.2  
**产品名称**：FictionForge  
**一句话定位**：一款纯本地运行的 Windows 桌面 AI 短篇小说写作工具，将散乱资料解析为可复用的设定知识库，并基于用户自带 API Key 与自定义文风进行可控续写/重写。

---

## 0. 产品假设与边界（基于澄清）

| 维度 | 决策 |
|------|------|
| 登录/账号 | 无登录，纯本地应用，数据存储在本机 |
| 平台 | 仅 Windows 桌面端 |
| 协作 | 不支持多人协作 |
| AI 能力 | 用户自带 API Key，平台不提供模型服务 |
| 内容安全 | 允许 NSFW、暴力、敏感政治等成人内容，不做内容审核 |
| 解析确认 | 提供解析准确率阈值选项；用户可设置“解析结果必须人工确认后导入知识库” |
| 文风卡 | 维度固定但由 AI 自定义内容；支持上传样例文段；支持跨作品文风 |
| 导出 | 支持 json / txt 导出 |
| 隐私 | 用户文档不会上传，全部本地处理 |
| 文档大小 | 无上传大小限制，但显示文档大小 |
| 语言 | 仅中文 |
| 付费 | 完全免费，无付费功能 |

## 1. 产品定位

FictionForge 是一款面向中文短篇小说创作者的 Windows 桌面 AI 写作工具。与云端 AI 写作服务不同，FictionForge 的核心价值是：

1. **本地隐私**：所有文档、知识库、生成记录均存储在本机，不上传用户创作内容。
2. **设定可控**：上传已有小说、设定集等资料，自动提取并整理为角色卡、世界观卡、术语卡、事件卡、文风卡；生成时按需选择知识卡，避免设定崩坏。
3. **文风可迁移**：支持从用户提供的样例文段中提炼文风，并跨作品复用。
4. **AI 自主接入**：用户配置自己的 API Key，直接调用模型，无需平台中转，无额外费用。

竞品参考：Sudowrite 的生成辅助、NovelAI 的文风生成、NovelCrafter 的项目与知识库管理。FictionForge 的差异化在于**纯本地、Windows 桌面、完全免费、用户自带 Key、允许成人内容**。

## 2. 目标用户

| 用户类型 | 特征 | 核心诉求 |
|---------|------|---------|
| 短篇小说作者 | 有完本或半成品作品，希望延续文风与设定创作新短篇 | 文风一致、设定不崩、快速产出 |
| 网文/同人作者 | 设定多、角色多，需要维护设定集，经常续写场景 | 知识库管理、角色/世界观一致 |
| 写作爱好者 | 喜欢用 AI 辅助，但希望结果可控，不想被 AI 带偏 | 低门槛、可编辑、可复用 |
| 成人/敏感内容创作者 | 需要写作自由，不接受内容审核，注重隐私 | 本地存储、无审核、自带 Key |

## 3. 核心用户故事

### 故事 A：旧作资料激活成新短篇

> 我是一名短篇小说作者，手头有过去写的几篇同一世界观的小说。我希望把旧文档导入后，系统能自动提取出角色、世界观、术语和文风。之后我创建新项目，选择“沿用旧作文风”，输入新场景开头，AI 能按照我熟悉的文风续写，并且不会搞错角色关系和世界观规则。

**关键动作**：导入文档 → 自动解析 → 审核知识卡 → 选择文风卡 → 续写新内容。

### 故事 B：长篇设定下快速续写场景

> 我正在写一个连载短篇系列，角色和设定已经很复杂。我希望在创作某个章节时，可以勾选本章涉及的角色卡、术语卡和世界观卡，让 AI 在续写时只基于这些设定生成，避免出现设定冲突。生成后我能对比多个候选，挑选最符合预期的一段。

**关键动作**：创建章节 → 选择上下文知识卡 → AI 续写 → 多候选对比 → 采纳编辑。

### 故事 C：重写段落以匹配目标文风

> 我写了一段初稿，但感觉太平淡，想要更悬疑、更紧张的文风。我希望选中这段文字，选择“悬疑文风卡”，并附加指令“加快节奏、增加短句”，AI 能给出几个不同风格的重写结果，同时保留原有的人名、术语和关键情节。

**关键动作**：选中段落 → 点击重写 → 选择文风卡 → 输入风格指令 → 生成候选 → 替换/合并。

### 故事 D：从灵感开始创建短篇项目

> 我只有一个模糊灵感：“一个能听见植物说话的女孩”。我希望系统能根据这句话生成角色设定、世界观规则、术语表和短篇大纲。我确认并修改后，直接基于大纲生成第一章初稿。

**关键动作**：输入灵感 → 生成设定问卷/大纲 → 确认知识卡 → 生成正文。

## 4. 功能清单

### 4.1 MVP 必须做

**应用与数据管理**
- 本地项目创建、打开、删除、归档
- 本地数据目录选择与查看
- 无登录、无云同步
- 应用设置中配置 API Key、模型、数据目录

**文档导入与解析**
- 支持导入 txt、markdown、docx 文件
- 显示文档名称、格式、大小
- 自动解析并提取：
  - 文风特征
  - 角色设定
  - 世界观设定
  - 术语表
  - 关键事件
- 解析准确率阈值设置（高/中/低）
- 解析结果预览：分类展示候选知识卡
- 支持逐张勾选、编辑后导入知识库
- 可选设置：所有解析结果必须人工确认后才能进入知识库

**知识库管理**
- 文风卡：叙事视角、时态、句式长度、节奏、对话风格、常用词汇、标点习惯、参考文段；维度固定，内容由 AI 生成并可手动编辑
- 角色卡：姓名、别名、身份、外貌、性格、动机、关系、语言风格、关键经历
- 世界观卡：时代背景、地理、势力、规则、科技/魔法体系、社会结构、禁忌
- 术语表：术语、定义、别名、使用场景
- 事件卡：时间、地点、参与者、摘要、影响
- 支持手动新建、编辑、删除、搜索
- 支持上传样例文段提炼文风卡
- 支持跨项目复制/引用文风卡

**写作编辑器**
- 章节/场景管理：创建、排序、折叠
- 基础富文本编辑
- 章节字数统计
- 自动保存到本地

**AI 生成**
- AI 续写：在光标处或章节末尾续写
- AI 重写：选中文本后重写
- 生成参数：目标字数、温度、叙事视角
- 生成时选择应用的知识卡：文风卡、角色卡、世界观卡、术语卡
- 一次生成 2-3 个候选，支持复制、采纳、重新生成
- 生成历史记录

**版本与导出**
- 章节版本快照，可回滚
- 项目导出为 docx / txt / markdown（澄清：主要支持 json / txt，可根据需求保留 docx）
- 知识库导出为 json / txt

**内容安全**
- 不做内容审核，无敏感词过滤
- 提供用户免责声明

## 5. 核心用户流程图

### 流程一：导入资料 → 建立知识库 → 续写

1. 用户启动 FictionForge，进入本地项目列表。
2. 点击「新建项目」，输入项目名称、类型。
3. 进入项目工作台，点击左侧「文档」。
4. 点击「导入文档」，选择本地 txt/md/docx 文件。
5. 系统读取文件并显示文件信息（名称、格式、大小）。
6. 系统调用 AI 进行解析，生成候选知识卡。
7. 用户设置解析阈值与人工确认选项；若开启人工确认，则勾选/编辑后点击「确认导入」。
8. 知识卡进入知识库。
9. 用户进入「章节」页，新建章节，开始写作或粘贴已有开头。
10. 点击「AI 续写」，在右侧面板选择文风卡、角色卡、世界观卡、术语卡。
11. 设置字数、温度等参数，点击「生成」。
12. 系统调用用户 API Key 生成 2-3 个候选。
13. 用户在候选面板对比，选择「采纳」，内容插入编辑器。
14. 用户继续编辑，保存章节，按需导出项目。

### 流程二：重写段落

1. 用户进入章节编辑器，选中需要重写的段落。
2. 点击工具栏「AI 重写」。
3. 在弹窗中选择文风卡、目标风格指令（如“更悬疑”“更抒情”）。
4. 勾选需要保持的角色、术语、世界观卡。
5. 点击「生成」，系统调用 API 返回多个重写候选。
6. 用户对比候选，采纳、部分复制或重新生成。
7. 采纳后系统自动保存章节版本，支持回滚。

### 流程三：从灵感创建项目

1. 用户在项目列表点击「灵感创作」。
2. 输入一句话灵感，如“一个能听见植物说话的女孩”。
3. 系统调用 AI 生成短篇大纲、角色草案、世界观草案、术语草案。
4. 用户逐项确认、修改，导入知识库。
5. 用户选择第一章场景，点击「生成初稿」。
6. 系统基于知识库生成初稿，用户继续编辑。

## 7. 数据实体初步草案

| 实体 | 关键字段 | 说明 |
|------|---------|------|
| **Project** | id, title, description, genre, cover_path, data_dir, created_at, updated_at | 本地项目 |
| **Document** | id, project_id, filename, file_type, file_size, content_text, parse_status, imported_at | 用户导入的资料文档 |
| **KnowledgeCard** | id, project_id, type, title, content_json, source_doc_ids, created_at, updated_at | 通用知识卡基表，type 为 role/world/term/style/event |
| **CharacterCard** | card_id, name, aliases, role, appearance, personality, motivation, relationships, voice, arc | 角色卡 |
| **WorldCard** | card_id, era, location, factions, rules, tech_magic, society, taboos | 世界观卡 |
| **TermCard** | card_id, term, definition, aliases, usage | 术语卡 |
| **StyleCard** | card_id, name, source, narrative_voice, tense, sentence_length, pacing, dialogue_style, rhetoric, vocabulary, punctuation, sample | 文风卡 |
| **EventCard** | card_id, title, time, location, participants, summary, impact | 关键事件卡 |
| **Chapter** | id, project_id, parent_id, title, order, content, status, word_count, created_at, updated_at | 章节/场景 |
| **KnowledgeSnippet** | id, document_id, project_id, text, tags, card_id | 可溯源原文片段，用于追溯知识卡来源 |
| **GenerationRecord** | id, project_id, chapter_id, type, input_text, params_json, output_candidates, selected_output, created_at | AI 生成记录 |
| **VersionSnapshot** | id, chapter_id, content, note, created_at | 章节版本快照 |

**存储说明**：  
- 所有数据以本地文件形式存储，推荐使用 SQLite 或 JSON 文件系统；用户可选择数据目录。  
- 敏感信息（API Key）使用本地加密存储。  
- 不支持云同步，用户需手动备份或导出。

## 8. 成功指标（可选）

由于产品免费且无云端统计，若未来需评估使用情况，可加入**用户自愿开启的匿名使用统计**。建议指标：

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 激活率 | ≥ 70% | 首次启动后创建首个项目并导入文档的比例 |
| 解析采纳率 | ≥ 70% | 解析出的知识卡被用户采纳/保留的比例 |
| 生成采纳率 | ≥ 50% | AI 生成候选被部分或全部采纳的比例 |
| 周生成字数 | ≥ 3000 字/活跃用户 | 反映用户是否真正用于创作 |
| 项目 7 天留存 | ≥ 40% | 创建项目后 7 天仍活跃 |

**注意**：产品不上传用户文档，以上指标仅在用户同意匿名统计时收集。

## 9. 需要进一步确认的产品问题（补充）

虽然主要问题已澄清，仍存在以下细节需确认：

1. **文风卡维度**：固定维度具体包含哪些？是否允许用户自定义新增维度？
2. **API Key 管理**：需要支持哪些模型供应商？是否支持多 Key 轮询/切换？
3. **本地数据格式**：项目数据使用 SQLite 还是 JSON？用户是否关心可读性？
4. **备份机制**：是否需要自动备份？备份文件保存在哪里？
5. **成人内容**：是否需要内置“无审查”提示模板，还是完全由用户控制？
6. **解析准确率阈值**：具体如何定义高/中/低？是否按字段置信度显示？
7. **文档导入格式**：是否需要支持 PDF？PDF 解析依赖本地 OCR？
8. **Windows 版本**：支持 Windows 10/11？安装包还是便携版？
