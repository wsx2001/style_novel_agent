**文档版本**：v1.1（增量）  
**关联版本**：v1.0  
**更新日期**：2026-08-15

---

### 1. 需求背景

用户需要更灵活的模型配置能力：

- 添加多个 AI 服务提供商的 API Key，包括 **Opencode Go** 在内的多种服务商。
- 支持同一提供商配置多个 API Key，系统自动选择可用 Key 或合并可用模型。
- 添加 Key 后自动获取该 Key 下所有可用模型列表；若获取失败，明确提示“未获取到模型”。
- 项目级允许切换使用的提供商和模型，不影响全局设置。
- 切换模型后，对话中显示切换提示；生成记录中记录实际使用的提供商和模型。

### 2. 功能设计

#### 2.1 模型提供商管理（全局设置）

**新增“模型提供商”标签页**，管理所有已添加的 AI 服务商。

**提供商列表**：
- 显示已添加的提供商，包含名称、类型、API Key 数量、状态、模型数量、默认标记。
- 支持添加、编辑、删除提供商。

**添加提供商流程**：

1. 用户点击「添加提供商」。
2. 弹出配置窗口：
   - **提供商类型**：下拉选择，预设类型包括：OpenAI、Anthropic、DeepSeek、Kimi、Opencode Go、自定义 OpenAI 兼容、其他。
   - **名称**：自定义显示名称。
   - **API Key 列表**：可动态添加多个 API Key 输入框，每个 Key 可单独标记启用/禁用。
   - **Base URL**（可选，适用于自定义兼容接口）。
   - **验证并获取模型列表**：点击后系统使用所有已启用的 API Key 请求模型列表。
3. 系统合并所有 Key 返回的模型列表（去重），并记录每个 Key 可访问的模型。
4. 若获取失败，弹出提醒：“**未获取到模型**”，但仍允许保存 Key（可稍后手动获取或手动添加模型 ID）。
5. 用户可勾选默认启用的模型，或全部启用。
6. 点击「保存」，提供商添加完成。

**API Key 状态检测**：
- 每个 Key 可单独点击「检测连接」，系统发起轻量请求验证有效性，并刷新该 Key 的模型列表。
- Key 失效时显示警告标识。

**模型列表管理**：
- 每个提供商下展示合并后的模型 ID 列表。
- 支持手动添加模型 ID（用于无法自动获取或自定义模型名称的场景）。
- 支持启用/禁用特定模型，禁用的模型在项目选择器中不可见。

**默认提供商与模型**：
- 用户可设置一个全局默认提供商和默认模型。
- 新项目默认继承全局默认，但可在项目内覆盖。

**多 API Key 策略**：
- 一个提供商可配置多个 API Key。
- 系统在生成时自动选择第一个可用的 Key（可按顺序或随机轮询）。若首选 Key 不支持所选模型，则自动尝试其他 Key。
- 用户可在提供商设置中手动调整 Key 优先级或指定默认 Key。

#### 2.2 项目级模型切换

**在项目设置页新增“模型”配置区域**：

- 显示当前项目使用的提供商和模型。
- 下拉选择提供商（来自全局已添加的提供商）。
- 选择提供商后，自动加载该提供商下已启用的模型列表，供用户选择具体模型。
- 可设置该项目的默认模型，所有对话和生成默认使用此模型。
- 提供“继承全局默认”选项，若不设置则使用全局默认。

**在 AI 对话工作台快捷切换**：

- 顶部工具栏增加「当前模型」显示（如：`OpenAI · gpt-4o`）。
- 点击可弹出下拉菜单，列出当前项目可用的所有提供商和模型（来自全局启用列表），用户可快速切换。
- 切换后，仅影响后续生成消息，不影响已有消息。
- **切换提示**：对话流中自动插入一条系统消息，内容为“**模型已切换为：{提供商} · {模型}**”。
- 若当前项目未指定模型，则使用全局默认。

#### 2.3 思维深度与模型的关系

- 思维深度等级（无/自动/低/中等/高/极高）继续采用统一等级，不针对不同模型 API 暴露具体参数映射。
- 系统内部根据所选模型类型自动适配参数，用户无需关心。
- 若所选模型不支持某些思维深度等级对应的底层参数，系统自动降级或采用近似实现，并在 UI 上提示“该模型可能不支持极高思维深度”。

### 3. 数据实体更新

**新增 `ModelProvider` 实体**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 提供商唯一标识 |
| name | string | 用户自定义名称 |
| type | enum | 提供商类型：openai / anthropic / deepseek / kimi / opencode_go / custom / other |
| base_url | string | 自定义 Base URL（可选） |
| api_keys_json | JSON | 存储多个 API Key 及其状态、优先级、可访问模型列表，结构见下方说明 |
| models_json | JSON | 合并后的可用模型列表，包含模型 ID 和启用状态 |
| is_default | boolean | 是否全局默认提供商 |
| created_at | datetime | 创建时间 |
| updated_at | datetime | 更新时间 |

**`api_keys_json` 结构示例**：

```json
[
  {
    "key_id": "key_1",
    "api_key_encrypted": "加密后的字符串",
    "enabled": true,
    "priority": 1,
    "available_models": ["gpt-4o", "gpt-4o-mini"]
  },
  {
    "key_id": "key_2",
    "api_key_encrypted": "加密后的字符串",
    "enabled": true,
    "priority": 2,
    "available_models": ["gpt-4o"]
  }
]
```

**修改 `Project` 实体**，增加字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| default_provider_id | string | 项目默认提供商 ID，可为空（继承全局） |
| default_model_id | string | 项目默认模型 ID，可为空（继承提供商默认） |

**修改全局设置**，增加字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| global_default_provider_id | string | 全局默认提供商 ID |
| global_default_model_id | string | 全局默认模型 ID |

**修改 `GenerationRecord` 实体**，增加字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| provider_id | string | 本次生成实际使用的提供商 ID |
| model_id | string | 本次生成实际使用的模型 ID |

### 5. 交互流程

#### 流程：添加提供商（多 Key）并获取模型列表

1. 用户进入「全局设置」→「模型提供商」。
2. 点击「添加提供商」。
3. 选择提供商类型（如 Opencode Go），输入名称。
4. 在 API Key 列表中添加一个或多个 Key，设置优先级。
5. 点击「验证并获取模型列表」。
6. 系统使用每个启用的 Key 请求模型列表。
7. 若所有 Key 均获取失败，弹出提醒“未获取到模型”，但用户仍可保存 Key 并手动添加模型 ID。
8. 若至少一个 Key 成功，合并去重模型列表，并记录每个 Key 支持的模型。
9. 用户勾选启用模型，保存。
10. 可设为全局默认。

#### 流程：项目内切换模型

1. 用户进入项目设置，找到「模型」区域。
2. 选择「否」关闭继承全局默认。
3. 从提供商下拉选择目标提供商，系统自动加载该提供商下已启用模型列表。
4. 选择具体模型，点击「保存」。
5. 回到对话工作台，顶部模型显示更新，后续生成使用新模型。
6. 对话流中自动插入系统提示：“模型已切换为：{提供商} · {模型}”。

#### 流程：生成时记录实际使用的提供商和模型

- 每次生成请求，系统记录本次实际使用的 `provider_id` 和 `model_id` 到 `GenerationRecord` 中，供后续回溯。

### 6. 成功指标（可选）

- 多提供商配置率：至少添加 2 个提供商的用户比例 ≥ 30%。
- 多 Key 配置率：单个提供商下配置多于 1 个 Key 的比例 ≥ 10%。
- 项目级模型切换使用率：在项目内自定义模型的比例 ≥ 20%。
- 模型获取成功率：成功自动获取模型列表的比例 ≥ 90%（排除用户网络问题）。
- 切换提示可见性：切换模型后显示系统消息的比例 100%。
